# Notes for agents working in this repo

## Start here (every BuddhistAI repo)

- Read the maintainer handbook first: https://buddhistai.github.io/knowledge-base/handbook/ (source: BuddhistAI/knowledge-base `handbook/`). Follow its rules and conventions.
- Check the Development board for cards assigned to you: https://github.com/orgs/BuddhistAI/projects/3. Status and next steps: `handbook/status.md`.
- Rules: plain English for non-native readers, no idioms. "Buddhist tasks", not only texts. "Top performance" and "Best value". Neutral credits: WeBuddhist is one contributor among others. Never invent data, scores, votes or links. Never edit generated files by hand.
- buddhist-benchmarks stays clean (short `result.json`, outputs, scores). Provenance records (`buddhistai/provenance@1`) live in the skill's own repo.
- When you change something the handbook describes, update the handbook in the same pull request.
- Before you change anything users see (pages, forms, install steps, app screens), write a design in `docs/designs/` and run an EGM review with our personas: skills `buddhistai-elephant` and `buddhistai-ux-review` (handbook `ux.md`). Small text or bug fixes skip this.
- EGM artifact directory: docs/designs
- This repo: the knowledge base and the handbook (Jekyll site). Run `python3 scripts/build.py`, then `python3 scripts/check.py`.

## This repo

- This is the BuddhistAI knowledge base: task definitions (`tasks/<task-id>.md`), the workflows tasks come from (`workflows/<id>.md`), and experiments (`experiments/<yyyy-mm>-<slug>/` with PLAN.md, LOG.md, REPORT.md; rules in `experiments/README.md`). Framing is Buddhist tasks, not only texts.
- Task IDs are shared with buddhist-benchmarks `tasks/index.json` and buddhist-skills skill names (`<task>-<language>`). A new task page needs a matching (planned) entry there.
- Workflows have an owner. A `linked` workflow lives in its owner's document: summarize it in our own words and link it, never copy it. A `hosted` workflow's owner reviews changes (CODEOWNERS).
- Never hand-edit the README index tables or the "Found in workflows" blocks. Run `python3 scripts/build.py`, then `python3 scripts/check.py`.
- The Directory (`directory/`) lists Buddhist AI projects and datasets. Entries live only in `directory/projects.yml` and `directory/datasets.yml`; the tables in `directory/README.md` are generated by `scripts/build.py`. Verify every link before adding an entry, never invent one, describe without ranking, and write "license not stated" when you cannot find the license.
- Credit people in `contributors`. Neutral branding: WeBuddhist is one contributor among others.
- Workflow pages are semver-versioned in `version`; `source_version` is the owner's own version.
- Experiments: write PLAN.md before running and never edit it after the start (log deviations in LOG.md); numbers in a report must link to a results file at an exact commit or version. Keep the table in `experiments/README.md` current.
- Plain English: many readers are non-native speakers. Short, literal sentences, no idioms.
- `handbook/` is the maintainer and developer handbook (mission, rules, architecture, conventions, how-to guides, status and roadmap). When you change how any BuddhistAI repo, site, workflow or rule works, update the handbook in the same PR. Keep `handbook/status.md` current.
